# Publishing on Nexus Mods

We publish on Nexus only (for now): **one page per mod** + **one "MC Valheim - All Mods" pack page**.
Everything to upload is generated by `./tools/Package-Mod.ps1` into `dist/nexus/`; nothing is uploaded
automatically. Facts below were checked against the Nexus upload form, help pages and the Vortex source in
September 2026 (see `docs/research/` for the research notes).

## 1. Prepare the release

1. Every in-game test for the version passes (`./tools/Get-TestTodo.ps1`). Untested items can only ship with
   `-AllowPending`, and they are then listed on the page sheet.
2. Bump `<Version>` in the mod's csproj and add a `## x.y.z` entry to its `CHANGELOG.md`
   (one line per change; Nexus shows changelogs one line per entry).
3. Pack: bump `version` in `packaging/nexus/pack.json` and add an entry to `packaging/nexus/PACK_CHANGELOG.md`.
4. Commit, then run `./tools/Package-Mod.ps1 -Release` (all mods + pack) or `-Mod X` for one mod (no pack then:
   the pack always contains every mod).
   The release gate refuses: a dirty git tree, a missing changelog entry, failed tests, untested items (mod and
   framework tests, without `-AllowPending`), names/versions/texts that break Nexus rules, a pack version already
   released, and a mod whose code changed since its released version (bump its version). A mod already released
   and unchanged is simply reused in the pack. On success it creates local tags `nexus/<GUID>/v<version>` and
   `nexus/pack/v<version>` (all or nothing). A dry run of an already-released version writes to `<version>-dev`,
   never over the released files; a sheet built from uncommitted changes says "do not upload".

## 2. Create or update the page

Open `dist/nexus/<GUID>/<version>/nexus-page.md` (or `_Pack/<version>/`). It lists every value to enter:

| Step | What to do |
|---|---|
| General | Name, author (`MC`), version, category (suggested), summary (plain text, max 350), tags. |
| Description | Switch the editor to **source mode**, paste `description.bbcode.txt`, check the preview. |
| Media | Upload `thumbnail.png` (16:9) and set it as thumbnail; `header.png` (1300x372) as page header (optional). Real in-game screenshots are better: add them when you have them. |
| Requirements | Add **BepInExPack_Valheim** (https://www.nexusmods.com/valheim/mods/3605) as a file-to-file requirement on the main file, minimum 5.4.2350. For MC dependencies, add the required MC mod's main file. |
| Permissions | "Use recommended settings" or your own. Third-party content: No. |
| Files | Upload the zip. First time: **Add as new file**. Later: **Update existing file** (the previous main file) + **Archive existing file**. Keep the file **name** stable and without version (Vortex uses it to detect updates). Category: Main. Tick "Update mod version to match this file's version". |
| Changelog | Add the lines from the sheet under the version. |

To publish, Nexus needs: name, author, version, category, summary, a description different from the template,
at least one gallery image set as thumbnail, and at least one non-archived file.

After the first publish, put the page URL in `packaging/nexus/pages.json` (by GUID, or `pack`). Later packages
then cross-link: each mod's description links to the pack, the pack lists each mod's page.

## 3. AI tags (mandatory)

Nexus requires correct **Generative AI Usage** tags and moderates wrong or missing ones. Our tags (decided
2026-09-28):

- **AI Assisted**: development is led by the author (design, decisions, in-game testing) with AI help on the code.
  Nexus only accepts this tag with visible evidence of human-led development: development history, commit
  history or design notes, and the author must be able to explain the mod if asked. Keep such evidence on or linked
  from the page, otherwise moderators may switch the tag to "AI-Generated Content".
- **AI Media**: the description text and the placeholder images are AI-made.

Never publish a mod whose in-game tests have not been run: untested AI mods are treated as spam.

## 4. The pack

- One flat zip with every mod, same folders as the single downloads (so both can overwrite each other safely).
- **Allow mod manager download: No.** Vortex's community Valheim extension installs only the first DLL folder of
  an archive, so a Vortex user would silently get one mod out of the pack. The pack page tells Vortex users to
  install the individual mods instead. A Nexus Collection of the single mods is the Vortex-native alternative
  (created from Vortex, later).
- Publish every included mod first, so the pack never contains an unreleased version.
- Framed as a convenience bundle of our own mods (Nexus asks compilations to be more than a repack; our pack is
  the same files as the single pages, from the same author).

## 5. How players end up installing

| Method | Result |
|---|---|
| Manual (extract into the Valheim folder) | `BepInEx/plugins/MC_Valheim/<Category>/<GUID>/` |
| Vortex, single mod | `BepInEx/plugins/<GUID>/` (the Valheim extension flattens folders; the mod works the same) |
| Vortex, pack | Disabled (see above) |

Players should not mix a Vortex install and a manual install of the same mod (two copies of one GUID: BepInEx
loads only the newest and warns). Settings always live in `BepInEx/config/<GUID>.cfg`, whatever the method.

## 6. Rules to keep in mind

- Never ship game files (no Valheim or Unity DLLs, no publicized assemblies, no game assets). Our zips contain
  only our DLL, README.md, CHANGELOG.md and the mod's own Content files.
- Never ship `winhttp.dll`, `doorstop_config.ini` or anything under `BepInEx/core`, and never name a folder or
  zip "BepInExPack...Valheim": Vortex would treat the archive as a BepInEx pack.
- No zips inside zips, no password-protected archives (Nexus quarantines them).
- Names: letters, digits, space and `_ ' ( ) . -` only. File name max 50, summary max 350, file description max
  255, version letters/digits/`.`/`-` only. The pipeline checks these.
- No advertising other sites, no asking for endorsements or donations, no unproven performance claims.

## 7. Automating uploads later (not set up)

Nexus has an official Upload API (v3, https://api-docs.nexusmods.com/) and a GitHub Action
(Nexus-Mods/upload-action). They can **add new versions to an existing file** and changelogs, authenticated with
your personal API key. They cannot create pages or edit page text, so the first release of every page stays manual.
The mod-file endpoints are marked experimental. When there are several pages to update regularly, a
`tools/Publish-Nexus.ps1` using the key from an environment variable could upload new versions in one command.
