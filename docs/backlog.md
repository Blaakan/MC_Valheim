## Combat

### Crossbow revamp

> Stays loaded

- **Scope:** QoL · **Feasibility:** easy · **Who needs it:** Client · **Custom assets:** no · **Status:** [Crossbow Stays Loaded 0.1.0](../src/Combat/Crossbow.StaysLoaded) (in development)
- **Approach:** Keep a per-item flag in ItemData.m_customData (e.g. 'VM.CrossbowLoaded'), which is persisted in inventories, chests, drops and saves and ignored by vanilla. A postfix on the private Player.SetWeaponLoaded sets the flag when the weapon is non-null. A postfix on Attack.OnAttackTrigger clears it only when the shot actually fired, i.e. the character is no longer loaded. A prefix on the private Player.UpdateWeaponLoading instantly calls SetWeaponLoaded(weapon) and skips the reload queue when the newly equipped crossbow is flagged. Vanilla unequip paths keep nulling m_weaponLoaded harmlessly, and the ZDO WeaponLoaded bool keeps visuals correct for all players.
- **Hooks:** `Player.SetWeaponLoaded`, `Player.UpdateWeaponLoading`, `Attack.OnAttackTrigger`, `Attack.GetWeapon`, `Player.ResetLoadedWeapon`, `Humanoid.UnequipItem`, `ItemDrop.ItemData.GetTooltip`
- **Risks:** Pre-loading several crossbows enables instant swap volleys, so add a config option to remember only the last loaded one. Ammo is consumed at fire time, so there is no ammo dupe. The target methods are private (AccessTools or a publicized assembly) and may be renamed by game patches. Any m_requiresReload weapon from content mods is affected, which is generic and intended.
- **Game systems:** [docs/game/combat.md](game/combat.md)
- **Existing mods:** full

Ours: a per-item persisted flag (for example ItemData.m_customData) restored on equip, covering every m_requiresReload weapon (crossbows, Dundr, modded), with a clear rule for drop and trade and optional persistence across logout. The gap is simply a maintained, 1.0-verified version.

### Increase base HP/Stamina with stats

> (running jump etc)

- **Scope:** Revamp · **Feasibility:** easy · **Who needs it:** Client · **Custom assets:** no · **Status:** idea
- **Approach:** Postfix the private Player.GetTotalFoodValue (out hp, stamina, eitr) to add capped bonuses from skill levels (Run, Jump, Swim, Blocking) or PlayerProfile stats (DistanceRun, Jumps). Optionally mirror the bonus into m_baseHP so GetBaseFoodHP and the HUD stay consistent. Max HP propagates through the player's own ZDO max_health.
- **Hooks:** `Player.GetTotalFoodValue`, `Player.m_baseHP`, `Player.m_baseStamina`, `Player.GetBaseFoodHP`, `Skills.GetSkillFactor`, `PlayerProfile.GetStat`
- **Risks:** UpdateFood recalculates every second, so setting max HP anywhere else is overwritten. Other food or vitals mods (ValheimPlus food config and similar) patch the same place, so ordering matters. Skill loss on death lowers the bonus. PvP balance needs synced config.

### Sneak revamp

> gain xp on sneak attack, make ennemies spot you less easily early

- **Scope:** Revamp · **Feasibility:** easy · **Who needs it:** Client · **Custom assets:** no · **Status:** idea
- **Approach:** Prefix Character.Damage, which runs on the attacker's machine. If the attacker is the local player, the target's BaseAI is not alerted (synced from ZDO alert) and backstabBonus > 1, raise Sneak and remember the victim for 300 s. Postfix Player.UpdateStealth to multiply the stealth target by a bonus that fades with Sneak skill or boss progression, and scale noise in RPC_AddNoise. Both values sync through ZDO, so the change stays client-only.
- **Hooks:** `Character.Damage`, `BaseAI.IsAlerted`, `Player.RaiseSkill`, `Player.UpdateStealth`, `Player.GetStealthFactor`, `Character.RPC_AddNoise`, `BaseAI.CanSeeTarget`, `MonsterAI.UpdateTarget`
- **Risks:** Attacker-side prediction can diverge from the victim-owner backstab rule (per-victim cooldown, PassiveMobs sight check); an optional owner-to-attacker RPC can fix this when both sides have the mod. Changing monster view angle or range would need everyone to install it. Other stealth-overhaul or EpicLoot sneak effects patch the same methods.
- **Related:** Mob AI revamp
- **Game systems:** [docs/game/combat.md](game/combat.md)

### Balista revamp

> Better AI, target assignement

- **Scope:** Revamp · **Feasibility:** medium · **Who needs it:** Both · **Custom assets:** no · **Status:** idea
- **Approach:** Replace the closest-creature pick with a score: threat (targeting a player or a structure), low HP, distance, and a claim cap derived from other turrets' networked targets (RPC_SetTarget reaches everybody). Keep the current target unless a much better one appears. Sphere-cast the line of fire to skip shots that would hit players, tames or walls. Add gravity compensation using Projectile.m_gravity. Make HitType.Turret bolts ignore players and tames in Projectile.IsValidTarget.
- **Hooks:** `Turret.UpdateTarget`, `Turret.UpdateAttack`, `Turret.UpdateTurretRotation`, `Turret.ShootProjectile`, `Turret.RPC_SetTarget`, `Projectile.IsValidTarget`, `BaseAI.FindClosestCreature`, `MonsterAI.GetTargetCreature`, `MonsterAI.GetStaticTarget`
- **Risks:** Turret logic runs on whichever client owns the turret, so claim logic must use networked data only. Performance with many turrets requires throttling. Must not break ammo and trophy targeting. Turret-adding mods inherit the patch, so filter by config.
- **Related:** Mob AI revamp

### Better tower shields

> Make them usable. I see them as a immovable wall that can't parry: The player should be slowed A LOT but should be able to block virtually anything

- **Scope:** Revamp · **Feasibility:** medium · **Who needs it:** Client · **Custom assets:** no · **Status:** idea
- **Approach:** Identify tower shields from a configurable list (ShieldWoodTower, ShieldBoneTower, ShieldIronTower, ShieldBlackmetalTower, ShieldFlametalTower, ShieldGoldTower) and force m_timedBlockBonus <= 1 so they cannot parry. While blocking with one: apply a local SE_Stats with m_speedModifier around -0.6 (also slows turning) from an UpdateBlock postfix. In an RPC_Damage prefix, make frontal non-environmental hits blockable. After BlockAttack, scale down residual damage, stagger and pushback. Rear hits and stamina remain the counterplay.
- **Hooks:** `Character.RPC_Damage`, `Humanoid.BlockAttack`, `Humanoid.UpdateBlock`, `Player.GetJogSpeedFactor`, `Humanoid.CheckRun`, `Character.ApplyPushback`, `ObjectDB.Awake`, `ItemDrop.ItemData.GetBlockPower`
- **Risks:** Some damage bypasses blocking (Aoe launch via ForceJump, DoTs, lava, falling), so the set of 'blockable anything' hit types needs deciding. EpicLoot and shield mods patch GetBlockPower/BlockAttack. RPC_Damage is hot and long, so use prefix only, no transpiler. PvP balance.
- **Related:** Weapon revamp

## Infrastructure proposed by the research

Shared building blocks the research agents recommended while assessing the ideas.

### [Infra] VMods.Core content registration helpers (prefab clone + register)

- **Feasibility:** medium · **Who needs it:** Both
- **Approach:** A shared library API (RegisterItem/Piece/Recipe/StatusEffect/Prefab) that clones vanilla prefabs under an inactive DontDestroyOnLoad root and validates names (no spaces or parentheses, unique hash). It de-duplicates SharedData on clones and injects content idempotently into ZNetScene (Awake prefix) and both ObjectDBs (Awake/CopyOtherDB postfix + UpdateRegisters). This is essentially a minimal in-house Jotunn; alternatively adopt Jotunn itself.
- **Risks:** Duplicate names throw inside vanilla Awake and can break world load. Items unregistered at Player.Load are permanently deleted. Prefab edits persist across sessions (idempotency). The SharedData sharing semantics need a runtime check.

### [Infra] Mod version handshake (mod parity check)

- **Feasibility:** easy · **Who needs it:** Both
- **Approach:** Register a peer RPC in an OnNewConnection postfix. The client sends {guid, version, required} for every VMods plugin. The server validates in an RPC_PeerInfo prefix and rejects with Error(3) plus a readable reason sent first via RemotePrint or a custom RPC. The client mirrors the check against the server's list. Per-mod policy: required, optional, or client-only.
- **Risks:** Must not block vanilla-compatible client-only mods. Message ordering relies on the reliable channel. Crossplay console players are excluded from required-mod servers.

### [Infra] Server-authoritative config sync

- **Feasibility:** medium · **Who needs it:** Both
- **Approach:** Mark config entries as server-synced. On peer ready, the server pushes a compressed ZPackage of values; on change, it re-broadcasts. Clients override their local values while connected and restore them on disconnect. Could wrap the ServerSync library instead of writing our own.
- **Risks:** Payload size on PlayFab relay. Admin-only edits need a socket-identity check (routed-RPC sender is spoofable). Values must be applied before owners use them.

### [Infra] Localization loader

- **Feasibility:** easy · **Who needs it:** Client
- **Approach:** Each mod ships translations/<Language>.json (or yaml) embedded. The core adds words in a SetupLanguage postfix with English fallback, and also immediately if the Localization instance already exists. It enforces the $vm_<mod>_ token prefix.
- **Risks:** The LRU cache keeps [token] placeholders if a token is used before registration. Tokens must be sent over the network instead of localized text.

### [Infra] Console command framework + live tuning knobs

- **Feasibility:** easy · **Who needs it:** Depends
- **Approach:** Register a 'vm <mod> <sub>' command tree in an InitTerminal postfix, with isCheat:false for diagnostics (status, dump ZDO keys, list registered content) and remoteCommand for admin server actions. A dev-build helper reads Terminal.TryTest* for live tuning.
- **Risks:** isCheat:true permanently flags characters as cheated. Cheat commands only run on the host or server.

### [Infra] Input helper with vanilla-consistent gating

- **Feasibility:** easy · **Who needs it:** Client
- **Approach:** VmInput.CanTakeInput() mirrors Player.TakeInput's UI checks. KeyboardShortcut config entries are evaluated via ZInput.GetKey/GetKeyDown, with optional gamepad chords via ZInput Joy* buttons.
- **Risks:** Real rebindable actions in the settings UI would need reflection into ZInput.m_buttons and are deferred to UX.

### [Infra] Network/persistence helpers (keys, owner RPC, session hashes)

- **Feasibility:** easy · **Who needs it:** Depends
- **Approach:** A typed key registry (static readonly int hashes with a vm.<mod>. prefix), per-session re-registration of session-only keys (server included), a RequestOwner/Apply-on-owner RPC pattern helper modeled on Container, and typed m_customData accessors (bool, int, float, compact json) with namespaced keys.
- **Risks:** Writing ZDOs as non-owner gets overwritten. m_customData is lost when stackable items merge. Keep payloads small (whole-ZDO resend).

### [Infra] Custom SoftRef asset injection (locations / dungeon rooms)

- **Feasibility:** hard · **Who needs it:** Both
- **Approach:** Generate an AssetID for mod prefabs and register an AssetLoader entry in AssetBundleLoader.Instance via reflection (Jotunn-style), then add ZoneLocation entries through a LocationList instance or a SetupLocations postfix. Only needed when Exploration features add locations or rooms.
- **Risks:** Relies on internal loader structures that can change per patch. Location placement is generated server-side in ghost zones, so the server must have the mod. World-gen changes are permanent in saves.

### [Infra] Runtime self-tests & topology test scripts

- **Feasibility:** medium · **Who needs it:** Depends
- **Approach:** A 'vm selftest' command asserts engine assumptions after spawn: SharedData reference sharing, registration round-trip, customData survival through drop/pickup/container, session hashes present. Scripts launch the local dedicated server (-nographics -batchmode) and two clients for single-player, host, and dedicated test matrices.
- **Risks:** The local dedicated server is 1.0.15 vs client 1.0.16 (both network 40). Keep them in sync for release validation.

### [Infra] Game.isModded policy

- **Feasibility:** trivial · **Who needs it:** Client
- **Approach:** The core plugin sets Game.isModded = true in Awake, as IronGate requests, and documents the consequence in user-facing READMEs.
- **Risks:** It disables achievements and achievement stats for users. This is a product decision the user must confirm.
